# Передача файлов по TCP

Клиент-серверное приложение на Python для передачи произвольного файла с одного компьютера на другой по собственному бинарному протоколу поверх TCP. Сервер обслуживает нескольких клиентов параллельно (по потоку на клиента) и выводит скорость приёма данных.

## Возможности

- передача файлов размером до 1 ТиБ без загрузки файла целиком в память (расход памяти около 1 МиБ на соединение);
- имя файла до 4096 байт в UTF-8;
- параллельное обслуживание нескольких клиентов;
- вывод мгновенной и средней скорости приёма раз в 3 секунды для каждого активного клиента (для коротких передач — один раз по завершении);
- сохранение файлов только в поддиректорию `uploads` с защитой от выхода за её пределы;
- автоматическое разрешение конфликтов имён: `file.txt`, `file (1).txt`, `file (2).txt`, …;
- проверка размера принятых данных и уведомление клиента об успехе или ошибке;
- удаление недокачанных файлов, корректное закрытие сокетов и файлов;
- ошибка одного клиента не влияет на остальных.

## Требования

- Python 3.8 или новее
- только стандартная библиотека, сторонние пакеты не нужны
- Linux, macOS или Windows

## Структура проекта

| Файл | Назначение |
|---|---|
| `server.py` | точка входа сервера: аргументы, создание `uploads/`, приём соединений, запуск потоков |
| `client.py` | точка входа клиента: чтение файла, отправка, вывод результата |
| `protocol.py` | описание протокола: константы, формирование и разбор заголовка и ответа, `recv_exact` |
| `client_handler.py` | обработка одного клиента на сервере: приём данных, запись, проверка размера, ответ |
| `storage.py` | безопасная обработка имени файла и атомарное создание файла в `uploads/` |
| `speed_monitor.py` | отдельный поток, который измеряет и печатает скорость приёма |

## Запуск

### Сервер

```
python server.py <порт>
```

Пример:

```
python server.py 5000
```

Сервер создаёт каталог `uploads` в **текущей директории** (откуда он запущен) и сохраняет туда все полученные файлы. Остановить сервер можно сочетанием `Ctrl+C`.

### Клиент

```
python client.py <путь_к_файлу> <хост> <порт>
```

Примеры:

```
python client.py video.mp4 localhost 5000
python client.py /home/user/data/archive.zip 192.168.1.10 5000
python client.py "C:\docs\report.pdf" example.com 5000
```

Путь к файлу может быть относительным или абсолютным, хост — DNS-именем или IP-адресом (IPv4 или IPv6). На сервер отправляется только имя файла без пути.

Клиент завершается с кодом `0` при успешной передаче и `1` при ошибке.

## Пример вывода

Сервер:

```
Слушаю порт 5000, файлы сохраняются в /home/user/uploads
[127.0.0.1:52896] приём файла 'big.bin', 200000000 байт
[127.0.0.1:52896] мгновенная: 1.16 ГиБ/с, средняя: 1.16 ГиБ/с
[127.0.0.1:52896] успешно: /home/user/uploads/big.bin
```

Клиент:

```
Передача успешна: файл сохранён как big.bin
```

или при ошибке:

```
Передача НЕ удалась: ошибка: размер не совпал: ожидалось 1000, сохранено 640
```

## Протокол

Все числа передаются в порядке байт big-endian.

### Запрос клиента

| Поле | Размер | Описание |
|---|---|---|
| Сигнатура | 4 байта | константа `FTP1` |
| Длина имени | 2 байта | от 1 до 4096 |
| Имя файла | N байт | UTF-8, без пути |
| Размер файла | 8 байт | от 0 до 2⁴⁰ |
| Содержимое | ровно «размер» байт | поток данных файла |

### Ответ сервера

| Поле | Размер | Описание |
|---|---|---|
| Статус | 1 байт | `0` — успех, `1` — ошибка |
| Длина сообщения | 2 байта | длина текста в байтах |
| Сообщение | M байт | текст в UTF-8 |

После отправки ответа сервер закрывает соединение.

### Схема взаимодействия

```
Клиент                                   Сервер
  │ ── подключение ─────────────────────▶ accept() → новый поток
  │ ── заголовок (имя, размер) ─────────▶ проверка заголовка
  │                                       создание файла в uploads/
  │ ── содержимое файла ────────────────▶ запись + подсчёт скорости
  │                                       проверка размера
  │ ◀─ ответ (статус + сообщение) ─────── закрытие соединения
```

Конец данных определяется по заявленному размеру файла, а не по закрытию соединения. Благодаря этому сервер отличает полную передачу от обрыва.

## Безопасность

Имя файла от клиента считается недоверенным вводом:

- из имени берётся только последний компонент пути (обрабатываются и `/`, и `\`), поэтому `../../etc/passwd` превращается в `passwd`;
- управляющие символы и символы `<>:"|?*` заменяются на `_`;
- пустые имена и `.` / `..` заменяются на `file`;
- длина имени ограничивается по байтам UTF-8 с сохранением расширения;
- файл создаётся атомарно (`O_CREAT | O_EXCL`), что исключает перезапись чужих файлов и гонки между потоками;
- используется `O_NOFOLLOW`, чтобы не следовать символическим ссылкам;
- итоговый путь дополнительно проверяется на нахождение внутри `uploads/`.

Сервер никогда не читает и не записывает больше байт, чем заявлено в заголовке.

## Обработка ошибок

Любая ошибка при работе с клиентом (неверная сигнатура, некорректное имя, обрыв соединения, таймаут 30 секунд без данных, несовпадение размера, ошибка диска) приводит к следующему:

1. частично записанный файл удаляется;
2. клиенту отправляется ответ со статусом ошибки (если соединение ещё живо);
3. соединение закрывается;
4. остальные клиенты и сам сервер продолжают работать.

## Вывод скорости

За вывод отвечает отдельный поток (`speed_monitor.py`). Для каждого активного клиента раз в 3 секунды печатаются:

- **мгновенная скорость** — байты за последний интервал, делённые на его длительность;
- **средняя скорость** — все принятые байты, делённые на время с начала передачи.

Если клиент был активен менее 3 секунд, отчёт печатается один раз при завершении передачи.

## Ограничения

- целостность проверяется только по размеру файла, контрольная сумма не используется;
- нет шифрования и аутентификации;
- нет докачки: при обрыве файл передаётся заново;
- число одновременных клиентов не ограничено (один поток на клиента).
