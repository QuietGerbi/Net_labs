# Multicast Discovery

Утилита для обнаружения запущенных на разных хостах (или процессах)
копий приложения через multicast-рассылку (поддерживает IPv4 и IPv6).

## Структура проекта

```
lab1/
├── README.md              # эта инструкция
├── run.py
├── requirements.txt                # точка входа (запускаемый скрипт)
└── app/
    ├── __init__.py        # экспортирует MulticastDiscovery
    ├── core.py             # класс MulticastDiscovery (вся логика обнаружения)
    └── cli.py              # разбор аргументов командной строки и main()
```

- `discovery/core.py` — сетевой сокет, join к multicast-группе,
  отправка/приём ANNOUNCE/DISCOVER/BYE, отслеживание живых пиров.
- `discovery/cli.py` — `parse_args()` и `main()`, обработка сигналов
  SIGINT/SIGTERM.
- `run.py` — тонкая точка входа, которая просто вызывает `main()`.

Используются модули как стандартной библиотеки Python так и библиотека psutil

## Требования

- Python 3.7+
- ОС: macOS/Windows/Linux

## Подготовка

Установите зависимости в корне проекта
```bash
pip install -r requirements.txt
```

## Запуск

Из корня проекта (там, где лежит `run.py`):

```bash
# IPv4-пример
python3 run.py <IPv4 multicast> [port] [net_interface]

# IPv6-пример
python3 run.py <IPv6 multicast> [port] [net_interface]
```
Где IPv4/6 в диапозоне мультикаст адресов, (optinal) port - порт от 1 до 65535 и (optional) net_interface - сетевой интерфейс на устройстве

Запустите скрипт в нескольких терминалах (или на нескольких машинах в
одной сети) с одинаковым multicast-адресом и портом — каждый экземпляр
начнёт видеть остальные и выводить список живых копий с их IP-адресами.

Остановка — `Ctrl+C` (или `SIGTERM`), при этом инстанс разошлёт `BYE`
перед выходом.

## Ускоренное обнаружение (DISCOVER)

Помимо периодического `ANNOUNCE` (heartbeat раз в 2 с), приложение использует
запрос `DISCOVER`, чтобы новая копия не ждала очередного heartbeat:

1. При запуске экземпляр отправляет в группу multicast-запрос `DISCOVER`
   (до 3 раз с интервалом 1 с; повторы прекращаются, как только найден хотя бы один пир —
   так учитывается возможная потеря UDP-пакетов).
2. Каждый уже работающий экземпляр, получив `DISCOVER`, немедленно отвечает
   сообщением `ANNOUNCE`, не дожидаясь своего heartbeat. Ответ уходит в multicast-группу,
   поэтому его получают все.

**Ограничение частоты ответов**

- *Коалесценция* — пока ответ уже запланирован, новые `DISCOVER` игнорируются.
- *Минимальный интервал* — не чаще одного `ANNOUNCE` в 0,5 с от одной копии
  (учитываются и heartbeat, и ответные сообщения).
- *Jitter* — случайная задержка ответа до 0,3 с, чтобы копии не отвечали одновременно.

Параметры задаются константами класса `MulticastDiscovery`:

| Константа | Значение | Смысл |
|-----------|----------|-------|
| `DISCOVER_RETRIES` | 3 | число попыток отправки `DISCOVER` при старте |
| `DISCOVER_RETRY_INTERVAL` | 1.0 | пауза между попытками, с |
| `RESPONSE_MIN_INTERVAL` | 0.5 | минимум между двумя `ANNOUNCE` одной копии, с |
| `RESPONSE_JITTER_MAX` | 0.3 | максимальная случайная задержка ответа, с |
