# Места — асинхронное сетевое взаимодействие

## О проекте

Консольное приложение на Python, которое по названию места находит варианты локаций,
а для выбранной локации показывает **текущую погоду** и **интересные места поблизости**.
Для каждого места выводятся название, расстояние до выбранной точки, тип места в скобках
и описание из Википедии. Данные берутся из четырёх публичных API:

| № | API | Назначение |
|---|-----|-----------|
| 1 | [GraphHopper Geocoding](https://docs.graphhopper.com/#operation/getGeocode) | поиск локаций по названию (координаты, названия) |
| 2 | [OpenWeatherMap Current Weather](https://openweathermap.org/current) | погода по координатам |
| 3 | [Wikipedia GeoData](https://www.mediawiki.org/wiki/Extension:GeoData#API) | статьи с координатами в окрестности точки (с типом координаты) |
| 4 | [Wikipedia TextExtracts](https://www.mediawiki.org/wiki/Extension:TextExtracts#API) | описание статей по их id (и краткое описание из Викиданных) |

## Как это работает

Используются `asyncio` и асинхронная HTTP-библиотека `aiohttp`.

Сценарий:

1. Пользователь вводит название (например, «Цветной проезд»).
2. Вызывается `find_locations` — запрос к GraphHopper, результат выводится списком.
3. Пользователь выбирает локацию.
4. Вызывается `load_location_info`, внутри которой:
   - **параллельно** (`asyncio.gather`) выполняются две независимые ветки:
     - запрос погоды (API 2);
     - цепочка для мест: запрос статей рядом (API 3) → один пакетный запрос описаний
       для всех найденных статей (API 4);
   - результаты собираются в один объект `LocationInfo`.
5. Только после получения готового объекта результат печатается пользователю.

Соблюдённые требования:

- вся логика — две функции-корутины (`find_locations` и `load_location_info`) без блокировок;
- независимые вызовы выполняются одновременно;
- зависимые вызовы оформлены цепочкой, промежуточные данные передаются как значения, а не через глобальное состояние;
- поэтапного вывода нет, всё выводится после сбора результата;
- блокировка есть только на итоговом результате (`asyncio.run` в консольном интерфейсе);
- сбой одной части (например, погоды) не ломает остальное — ошибка попадает в `LocationInfo.errors`.

### Ограничения API и обработка ошибки 429

- Описания мест запрашиваются **одним пакетным запросом** (`pageids=1|2|3...`), а не
  отдельным запросом на каждое место. Википедия отдаёт расширенные описания не более чем
  для 20 статей за запрос, поэтому `max_places` не стоит делать больше 20.
- При ответе `429 Too Many Requests` запрос автоматически повторяется (до 4 раз).
  Пауза берётся из заголовка `Retry-After`, а если его нет, растёт как 1, 2, 4, 8 секунд.
  Ожидание реализовано через `asyncio.sleep`, то есть без блокировок.
- Википедия требует осмысленный `User-Agent` с контактом. Он задаётся в `app/config.py`
  (`USER_AGENT`), подставьте туда свои данные.

### Тип места

Тип выводится в скобках после расстояния. Источники по приоритету:

1. краткое описание статьи из Викиданных (например, «памятник в Москве»);
2. если его нет — тип координаты из GeoData (`landmark`, `railwaystation` и т. д.),
   переведённый на русский;
3. если нет и его — скобки не печатаются.

Теги в Википедии заполняются вручную, поэтому у части статей их нет, а формулировки
кратких описаний могут быть разной длины. Теги OpenStreetMap (`bus_stop` и т. п.)
Википедия не использует.

## Установка и запуск

Требуется Python 3.10+.

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

### Ключи API

Нужны бесплатные ключи:

- GraphHopper: https://www.graphhopper.com/ (раздел Dashboard → API keys)
- OpenWeatherMap: https://openweathermap.org/api (новые ключи могут активироваться до пары часов)

Скопируйте `.env.example` в `.env` и впишите ключи (либо задайте переменные окружения
`GRAPHHOPPER_API_KEY` и `OPENWEATHER_API_KEY`):

```
GRAPHHOPPER_API_KEY=ваш_ключ
OPENWEATHER_API_KEY=ваш_ключ
```

### Запуск

```bash
python main.py
```

Пример:

```

Выберите номер (Enter — отмена): 1

============================================================
```

## Настройка

Параметры задаются в `app/config.py` в классе `Config`:

| Параметр | По умолчанию | Описание |
|----------|--------------|----------|
| `search_radius_m` | 1000 | радиус поиска статей вокруг точки, м (Википедия допускает 10–10000) |
| `max_places` | 20 | максимум мест в выдаче (лимит Википедии на описания за запрос — 20) |
| `max_locations` | 5 | максимум вариантов локаций в списке |
| `timeout_s` | 15 | таймаут HTTP-запроса, с |

Википедия возвращает статьи по возрастанию расстояния, поэтому при малом радиусе и
большом числе объектов в выдачу попадают только ближайшие. Чтобы увидеть более
далёкие места, увеличьте `search_radius_m`.
